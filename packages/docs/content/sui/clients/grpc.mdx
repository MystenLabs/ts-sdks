`SuiGrpcClient` talks to the full node gRPC API. It is the recommended default for application code
and SDK integrations: it reads directly from a full node, and it is the only client with real-time
subscriptions.

```typescript
import { SuiGrpcClient } from '@mysten/sui/grpc';

const client = new SuiGrpcClient({
	network: 'mainnet',
	baseUrl: 'https://fullnode.mainnet.sui.io:443',
});
```

For local development:

```typescript
const client = new SuiGrpcClient({
	network: 'localnet',
	baseUrl: 'http://127.0.0.1:9000',
});
```

Reading data, executing transactions, and querying history all work the same way here as on any
client — see [Querying data](/sui/clients/querying) and
[Signing and execution](/sui/transactions/signing-and-execution). The rest of this page covers what
is specific to gRPC.

## gRPC-specific options

Top-level gRPC methods are a superset of the shared API, adding fields where the transport exposes
more data than the common shape can carry:

| Option              | Available on                                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `include.protoJson` | `getTransaction`, `executeTransaction`, `signAndExecuteTransaction`, `waitForTransaction`, `simulateTransaction` |

`protoJson` returns the raw protobuf response alongside the parsed result, which is useful when you
need a field the unified shape does not expose yet:

```typescript
const result = await client.getTransaction({
	digest: '<TRANSACTION_DIGEST>',
	include: {
		effects: true,
		protoJson: true,
	},
});

const transaction = result.Transaction ?? result.FailedTransaction;
console.log(transaction.digest, result.protoJson);
```

## Transport options

By default, `SuiGrpcClient` uses `GrpcWebFetchTransport` from
[protobuf-ts](https://github.com/timostamm/protobuf-ts), which works in browsers and Node.js through
the Fetch API. The `GrpcWebFetchTransport` class, `GrpcWebOptions` type, and `RpcTransport` type are
re-exported from `@mysten/sui/grpc`, so you can configure a transport without adding
`@protobuf-ts/*` as a direct dependency.

### gRPC-web transport (default)

The default transport uses the gRPC-web protocol over HTTP/1.1 or HTTP/2. Pass
`GrpcWebFetchTransport` options to customize it:

```typescript
import { SuiGrpcClient, GrpcWebFetchTransport } from '@mysten/sui/grpc';

const transport = new GrpcWebFetchTransport({
	baseUrl: 'https://your-custom-grpc-endpoint.com',
	format: 'binary', // default is 'text' (base64-encoded)
	// Additional transport options like fetchInit
});

const client = new SuiGrpcClient({
	network: 'testnet',
	transport,
});
```

### Native gRPC transport

For server-side applications (Node.js, Bun, and others), use the native gRPC transport with
`@protobuf-ts/grpc-transport` and `@grpc/grpc-js`. This speaks HTTP/2 and the native gRPC protocol
rather than the gRPC-web translation layer.

```bash
npm install @protobuf-ts/grpc-transport @grpc/grpc-js
```

```typescript
import { SuiGrpcClient } from '@mysten/sui/grpc';
import { GrpcTransport } from '@protobuf-ts/grpc-transport';
import { ChannelCredentials } from '@grpc/grpc-js';

const transport = new GrpcTransport({
	host: 'fullnode.testnet.sui.io:443',
	channelCredentials: ChannelCredentials.createSsl(),
});

const client = new SuiGrpcClient({
	network: 'testnet',
	transport,
});
```

For local development without TLS, use `ChannelCredentials.createInsecure()` and a plain
`host: '127.0.0.1:9000'`.

## Using service clients

`SuiGrpcClient` exposes the generated gRPC service clients directly, for methods, read masks, and
filters the shared API does not cover:

| Service                        | Covers                                                              |
| ------------------------------ | ------------------------------------------------------------------- |
| `ledgerService`                | Objects, transactions, checkpoints, epochs, service info, list RPCs |
| `stateService`                 | Owned objects, dynamic fields, balances                             |
| `transactionExecutionService`  | Transaction execution                                               |
| `subscriptionService`          | Real-time streams                                                   |
| `movePackageService`           | Packages, functions, datatypes                                      |
| `nameService`                  | SuiNS lookup and reverse lookup                                     |
| `signatureVerificationService` | Signature verification                                              |
| `forkingService`               | Admin APIs for `sui-fork` instances only                            |

These clients are generated with [protobuf-ts](https://github.com/timostamm/protobuf-ts). Requests
that return entity data take a read mask naming the fields to return, and every call accepts an
`RpcOptions` argument where `abort` carries an `AbortSignal`. Reach for them when the top-level
method cannot express what you need — otherwise prefer the top-level method, which handles field
selection and response mapping.

### Ledger service

```typescript
// Get a transaction by digest, naming the fields to return
const { response } = await client.ledgerService.getTransaction({
	digest: 'ABC123...',
	readMask: { paths: ['digest', 'effects.status'] },
});

// Get current epoch information
const { response: epochInfo } = await client.ledgerService.getEpoch({});

// Node and chain metadata: chain id, epoch, checkpoint height, available range
const { response: info } = await client.ledgerService.getServiceInfo({});
```

### State service

```typescript
const { response } = await client.stateService.listOwnedObjects({
	owner: '0xabc...',
	objectType: '0x2::coin::Coin<0x2::sui::SUI>',
});

const { response: fields } = await client.stateService.listDynamicFields({
	parent: '0x123...',
});
```

### Move package service

```typescript
const { response } = await client.movePackageService.getFunction({
	packageId: '0x2',
	moduleName: 'coin',
	name: 'value',
});
```

### Name service

Use the raw name service when you need the complete `NameRecord` rather than only a target address:

```typescript
const { response } = await client.nameService.lookupName({ name: 'example.sui' });
const { response: reverse } = await client.nameService.reverseLookupName({ address: '0xabc...' });
```

### Signature verification service

```typescript
const { response } = await client.signatureVerificationService.verifySignature({
	message: {
		name: 'TransactionData',
		value: messageBytes,
	},
	signature: {
		bcs: { value: signatureBytes },
		signature: { oneofKind: undefined },
	},
	jwks: [],
});
```

## Raw list RPCs

`ledgerService` provides streaming `listCheckpoints`, `listTransactions`, and `listEvents` RPCs
underneath the [top-level query methods](/sui/clients/querying#transactions-and-events). Use them
directly when you need what those do not expose: disjunctive normal form (DNF) filters, extra
predicates, checkpoint range bounds, or `listCheckpoints`.

A filter is a list of `terms` ORed together, each term a list of `literals` ANDed together. Setting
`negated: true` inverts a literal:

```typescript
// Transactions that affected an address but were not sent by it
const stream = client.ledgerService.listTransactions({
	filter: {
		terms: [
			{
				literals: [
					{
						negated: false,
						predicate: {
							oneofKind: 'affectedAddress',
							affectedAddress: { address: '0xabc...' },
						},
					},
					{
						negated: true,
						predicate: { oneofKind: 'sender', sender: { address: '0xabc...' } },
					},
				],
			},
		],
	},
	readMask: { paths: ['digest'] },
});

for await (const frame of stream.responses) {
	if (frame.transaction) {
		console.log(frame.transaction.digest);
	}
}
```

Transaction predicates are `sender`, `affectedAddress`, `affectedObject`, `moveCall`, `emitModule`,
`eventType`, `eventStreamHead`, and `packageWrite`. Event predicates are `sender`, `emitModule`,
`eventType`, and `eventStreamHead`. An absent filter matches everything; a present filter needs at
least one term.

### Scan frames and watermarks

A list RPC is a stream of frames, not a single response. Each frame either delivers one item or just
reports progress, and every frame carries a `watermark` whose `cursor` is a safe resume point.
Exactly one frame of a successful stream carries `end`, reporting why the scan stopped:

| `end.reason`       | Meaning                                                          |
| ------------------ | ---------------------------------------------------------------- |
| `ITEM_LIMIT`       | The requested item limit was reached; that frame carries an item |
| `SCAN_LIMIT`       | The server's per-request scan budget was exhausted               |
| `CHECKPOINT_BOUND` | A requested checkpoint range bound was reached                   |
| `CURSOR_BOUND`     | An exclusive cursor bound was reached                            |
| `LEDGER_TIP`       | The scan reached the currently indexed ledger tip                |

`options.after` and `options.before` are canonical ledger-position bounds that mean the same thing
in both directions — ordering only controls the order of items within the interval — and they
intersect with `startCheckpoint`/`endCheckpoint` when both are given:

```typescript
import { GrpcTypes } from '@mysten/sui/grpc';

let resumeFrom: Uint8Array | undefined;
let reason: GrpcTypes.QueryEndReason | undefined;

// One request can stop before the interval is exhausted, so scan until it reports the ledger tip
do {
	const stream = client.ledgerService.listEvents({
		readMask: { paths: ['event_type', 'transaction_digest', 'event_index'] },
		startCheckpoint: 1_000_000n,
		options: {
			after: resumeFrom,
			limit: 100,
			ordering: GrpcTypes.Ordering.ASCENDING,
		},
	});

	for await (const frame of stream.responses) {
		// The latest watermark is always the safe place to resume from
		resumeFrom = frame.watermark?.cursor ?? resumeFrom;
		reason = frame.end?.reason ?? reason;

		if (frame.event) {
			console.log(frame.event.eventType, frame.event.transactionDigest);
		}
	}
} while (reason !== GrpcTypes.QueryEndReason.LEDGER_TIP);
```

A `SCAN_LIMIT` end reason means the scan stopped early, not that results are exhausted — which is
why the loop above reissues from the last watermark cursor rather than stopping.

## Subscriptions

`subscriptionService` provides filtered, real-time streams. Each subscription pairs with the list
RPC of the same name: same filter message, same item and watermark shapes, same cursor semantics.

| Method                  | Yields                                          |
| ----------------------- | ----------------------------------------------- |
| `subscribeCheckpoints`  | Checkpoints, and progress-only cursor frames    |
| `subscribeTransactions` | Executed transactions, and progress-only frames |
| `subscribeEvents`       | Emitted events, and progress-only frames        |

```typescript
const stream = client.subscriptionService.subscribeTransactions({
	filter: {
		terms: [
			{
				literals: [
					{
						negated: false,
						predicate: { oneofKind: 'sender', sender: { address: '0xabc...' } },
					},
				],
			},
		],
	},
	readMask: { paths: ['digest', 'effects.status'] },
});

for await (const frame of stream.responses) {
	if (frame.transaction) {
		console.log(frame.transaction.digest, frame.transaction.effects?.status?.success);
	}
}
```

Omit `filter` to receive everything.

### Frames and watermarks

A subscription behaves like an unbounded ascending scan, so frames report progress even when nothing
matches. Transaction and event frames carry a `watermark` on every frame and the item only when one
matched; checkpoint frames are checkpoint-granular and carry a `cursor` sequence number instead.

Two guarantees keep sparse filters alive: the first frame of a filtered subscription is always a
progress-only frame establishing the start position, and progress keeps advancing with bounded
staleness while no item matches. Track the cursor on every frame, not just the ones with items:

```typescript
let lastCursor: Uint8Array | undefined;

for await (const frame of stream.responses) {
	lastCursor = frame.watermark?.cursor ?? lastCursor;

	if (frame.transaction) {
		await handleTransaction(frame.transaction);
	}
}
```

### Cancelling a subscription

Subscription streams have no successful end — they run until cancelled by the client or terminated
by the server with a gRPC status. Pass an `AbortSignal` through `RpcOptions`:

```typescript
const controller = new AbortController();

const stream = client.subscriptionService.subscribeEvents(
	{ readMask: { paths: ['event_type', 'transaction_digest'] } },
	{ abort: controller.signal },
);

// Later, to tear the stream down
controller.abort();
```

### Recovering missed data

Subscriptions do not resume: a new subscription starts at the current tip, so anything that happened
while you were disconnected is skipped. Replay the gap with the paired list RPC before resuming live
delivery.

Scan between the last cursor you processed and the cursor the new subscription started at, passing
them as `options.after` and `options.before`. The indexed tip that the list RPC reads from can trail
the subscription's start position, so repeat until a scan actually reaches the upper bound, which
the terminal frame reports as `CURSOR_BOUND`:

```typescript
import { GrpcTypes } from '@mysten/sui/grpc';

async function replayGap(after: Uint8Array, before: Uint8Array) {
	let cursor = after;

	while (true) {
		const stream = client.ledgerService.listTransactions({
			readMask: { paths: ['digest'] },
			options: { after: cursor, before, limit: 100 },
		});

		let reason: GrpcTypes.QueryEndReason | undefined;

		for await (const frame of stream.responses) {
			cursor = frame.watermark?.cursor ?? cursor;
			reason = frame.end?.reason ?? reason;

			if (frame.transaction) {
				await handleTransaction(frame.transaction);
			}
		}

		// The bound was reached: the gap is fully replayed
		if (reason === GrpcTypes.QueryEndReason.CURSOR_BOUND) {
			return;
		}

		// The scan stopped at the indexed tip — wait for the index to catch up
		if (reason === GrpcTypes.QueryEndReason.LEDGER_TIP) {
			await new Promise((resolve) => setTimeout(resolve, 1000));
		}
	}
}
```

A durable consumer keeps two pieces of state: the last cursor it processed, and the start cursor
from the first frame of each new subscription. On reconnect, open the subscription first, buffer its
frames, replay the gap between those two cursors, then drain the buffer.

<Callout type="info">
	Subscriptions work over both transports, but in a browser long-lived streams are subject to
	connection limits and proxy timeouts. Treat disconnects as routine and always implement the replay
	path above.
</Callout>

For polling-based alternatives, see [live data over GraphQL](/sui/clients/graphql#live-data).
