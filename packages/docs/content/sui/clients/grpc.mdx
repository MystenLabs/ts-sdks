The `SuiGrpcClient` provides access to the Full Node gRPC API. It is the recommended default client
for application code and SDK integrations.

For more complete details on what is available through this API see the
[gRPC API docs](https://docs.sui.io/develop/accessing-data/grpc/what-is-grpc).

## Creating a gRPC client

To get started, create a `SuiGrpcClient` instance by specifying a network and base URL:

```typescript
import { SuiGrpcClient } from '@mysten/sui/grpc';

const grpcClient = new SuiGrpcClient({
	network: 'testnet',
	baseUrl: 'https://fullnode.testnet.sui.io:443',
});
```

For local development:

```typescript
const grpcClient = new SuiGrpcClient({
	network: 'localnet',
	baseUrl: 'http://127.0.0.1:9000',
});
```

## Using top-level methods

Use top-level methods for most application code. These methods match the shared
[Core API](/sui/clients/core) option and response shapes, so the same calls can also be written as
`grpcClient.core.<method>()` when SDK code needs the transport-agnostic `ClientWithCoreApi`
contract.

```typescript
import { SuiGrpcClient } from '@mysten/sui/grpc';

const grpcClient = new SuiGrpcClient({
	network: 'testnet',
	baseUrl: 'https://fullnode.testnet.sui.io:443',
});

const { balance } = await grpcClient.getBalance({
	owner: '<OWNER_ADDRESS>',
});

const { object } = await grpcClient.getObject({
	objectId: '<OBJECT_ID>',
	include: { content: true, display: true },
});

const coins = await grpcClient.listCoins({
	owner: '<OWNER_ADDRESS>',
	coinType: '0x2::sui::SUI',
});
```

Common top-level methods:

| Category       | Methods                                                                                                           |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| Objects        | `getObject`, `getObjects`, `listOwnedObjects`, `listDynamicFields`, `getDynamicField`                             |
| Coins          | `listCoins`, `getBalance`, `listBalances`, `getCoinMetadata`                                                      |
| Transactions   | `getTransaction`, `executeTransaction`, `signAndExecuteTransaction`, `waitForTransaction`                         |
| Simulation     | `simulateTransaction`                                                                                             |
| Queries        | `listTransactions`, `listEvents`                                                                                  |
| Move and names | `getMoveFunction`, `resolveNameServiceAddress`, `defaultNameServiceName`, `mvr.resolvePackage`, `mvr.resolveType` |
| Verification   | `verifyZkLoginSignature`                                                                                          |

### gRPC-specific top-level data

Top-level gRPC methods are a superset of the shared Core API where the transport can expose useful
gRPC data directly:

```typescript
const result = await grpcClient.getTransaction({
	digest: '<TRANSACTION_DIGEST>',
	include: {
		effects: true,
		protoJson: true,
	},
});

const tx = result.Transaction ?? result.FailedTransaction;
console.log(tx.digest, result.protoJson);
```

gRPC-specific options include:

| Option                     | Methods                                                                                   |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| `include.protoJson`        | `getTransaction`, `executeTransaction`, `signAndExecuteTransaction`, `waitForTransaction` |
| `include.protoJson`        | `simulateTransaction`                                                                     |
| `doGasSelection`           | `simulateTransaction`                                                                     |
| `include: { value: true }` | `listDynamicFields`                                                                       |

## Querying transactions and events

`listTransactions` and `listEvents` return filtered, cursor-paginated pages of history. They are
backed by the gRPC `LedgerService.ListTransactions` and `LedgerService.ListEvents` streaming RPCs,
and behave identically to the [Core API query methods](/sui/clients/core#query-methods) on the other
transports.

```typescript
import { SuiGrpcClient } from '@mysten/sui/grpc';

const grpcClient = new SuiGrpcClient({
	network: 'testnet',
	baseUrl: 'https://fullnode.testnet.sui.io:443',
});

// Most recent transactions sent by an address
const page = await grpcClient.listTransactions({
	filter: { sender: '0xabc...' },
	order: 'descending',
	limit: 20,
	include: { effects: true },
});

for (const result of page.transactions) {
	const transaction = result.Transaction ?? result.FailedTransaction;
	console.log(transaction.digest, result.$kind);
}

// Events emitted by a module, oldest first
const events = await grpcClient.listEvents({
	filter: { emitModule: '0xpkg...::my_module' },
	limit: 20,
});
```

Both methods take `filter`, `limit`, `order`, and one of the exclusive cursor bounds `after`
(ascending) or `before` (descending), and return `startCursor`, `endCursor`, and `hasNextPage`.
Continue an ascending read by passing `endCursor` as `after`; poll for newer items after a
descending read by passing `startCursor` as `after`.

```typescript
let cursor: string | null = null;

do {
	const page = await grpcClient.listEvents({
		filter: { eventType: '0xpkg...::my_module::MyEvent' },
		after: cursor,
		limit: 50,
	});

	for (const event of page.events) {
		console.log(event.checkpoint, event.transactionDigest, event.eventIndex, event.json);
	}

	// A short page can still have more results, so drive the loop off hasNextPage
	cursor = page.hasNextPage ? page.endCursor : null;
} while (cursor !== null);
```

<Callout type="info">
	gRPC servers bound how much of the ledger a single filtered request scans. A scan-limited page can
	return fewer items than `limit` — even zero — while still reporting `hasNextPage: true`. Continue
	from `endCursor` rather than stopping on a short page: each request makes progress through the
	scanned range. Servers also cap page sizes (50 by default) and silently truncate larger `limit`
	values.
</Callout>

Filters accept exactly one predicate: `sender` or `function` for transactions, and `sender`,
`emitModule`, or `eventType` for events. MVR names are resolved automatically. For combined,
negated, or additional predicates, and for checkpoint range bounds, use the
[raw ledger service](#ledger-service).

## Transport options

By default, `SuiGrpcClient` uses `GrpcWebFetchTransport` from
[protobuf-ts](https://github.com/timostamm/protobuf-ts), which works in browsers and Node.js through
the Fetch API. You can also provide a custom transport for advanced use cases.

The `GrpcWebFetchTransport` class, `GrpcWebOptions` type, and `RpcTransport` type are all
re-exported from `@mysten/sui/grpc` for convenience.

### gRPC-web transport (default)

The default transport uses the gRPC-web protocol over HTTP/1.1 or HTTP/2. You can customize it by
passing `GrpcWebFetchTransport` options directly:

```typescript
import { SuiGrpcClient, GrpcWebFetchTransport } from '@mysten/sui/grpc';

const transport = new GrpcWebFetchTransport({
	baseUrl: 'https://your-custom-grpc-endpoint.com',
	format: 'binary', // default is 'text' (base64-encoded)
	// Additional transport options like fetchInit
});

const grpcClient = new SuiGrpcClient({
	network: 'testnet',
	transport,
});
```

### Native gRPC transport

For server-side applications (Node.js, Bun, and others), you can use the native gRPC transport with
`@protobuf-ts/grpc-transport` and `@grpc/grpc-js`. This uses HTTP/2 with the native gRPC protocol
rather than the gRPC-web translation layer.

Install the required packages:

```bash
npm install @protobuf-ts/grpc-transport @grpc/grpc-js
```

Then create the client with a `GrpcTransport`:

```typescript
import { SuiGrpcClient } from '@mysten/sui/grpc';
import { GrpcTransport } from '@protobuf-ts/grpc-transport';
import { ChannelCredentials } from '@grpc/grpc-js';

const transport = new GrpcTransport({
	host: 'fullnode.testnet.sui.io:443',
	channelCredentials: ChannelCredentials.createSsl(),
});

const grpcClient = new SuiGrpcClient({
	network: 'testnet',
	transport,
});
```

For local development without TLS:

```typescript
import { GrpcTransport } from '@protobuf-ts/grpc-transport';
import { ChannelCredentials } from '@grpc/grpc-js';

const transport = new GrpcTransport({
	host: '127.0.0.1:9000',
	channelCredentials: ChannelCredentials.createInsecure(),
});

const grpcClient = new SuiGrpcClient({
	network: 'localnet',
	transport,
});
```

## Using service clients

The `SuiGrpcClient` exposes several service clients for lower-level access to the gRPC API. These
service clients are generated using [protobuf-ts](https://github.com/timostamm/protobuf-ts), which
provides type-safe gRPC clients for TypeScript. For more details on how to use gRPC with Sui, see
the [gRPC overview](https://docs.sui.io/develop/accessing-data/grpc/what-is-grpc).

### Prefer top-level methods first

For common operations, call the top-level method before reaching for raw service clients:

```typescript
import { SuiGrpcClient } from '@mysten/sui/grpc';

const grpcClient = new SuiGrpcClient({
	network: 'testnet',
	baseUrl: 'https://fullnode.testnet.sui.io:443',
});

await grpcClient.listCoins({
	owner: '<OWNER_ADDRESS>',
});
```

Use the generated service clients directly when you need gRPC methods, read masks, streaming
behavior, or filters that are not exposed by the top-level API.

### Transaction execution service

```typescript
const { response } = await grpcClient.transactionExecutionService.executeTransaction({
	transaction: {
		bcs: {
			value: transactionBytes,
		},
	},
	signatures: signatures.map((sig) => ({
		bcs: { value: fromBase64(sig) },
		signature: { oneofKind: undefined },
	})),
});

// IMPORTANT: Always check the transaction status
if (!response.finality?.effects?.status?.success) {
	const error = response.finality?.effects?.status?.error;
	throw new Error(`Transaction failed: ${error || 'Unknown error'}`);
}
```

### Ledger service

```typescript
// Get transaction by digest
const { response } = await grpcClient.ledgerService.getTransaction({
	digest: '0x123...',
});

// Get current epoch information
const { response: epochInfo } = await grpcClient.ledgerService.getEpoch({});
```

#### Raw list RPCs

The ledger service also provides streaming `listCheckpoints`, `listTransactions`, and `listEvents`
RPCs. For most use cases, prefer the corresponding
[top-level query methods](#querying-transactions-and-events), which handle pagination and filter
construction for you. Reach for the raw RPCs when you need what those methods do not expose:
disjunctive normal form (DNF) filters, additional predicates, checkpoint range bounds, or
`listCheckpoints`.

A filter is a list of `terms` that are ORed together, and each term is a list of `literals` that are
ANDed together. Setting `negated: true` on a literal inverts that predicate:

```typescript
// Transactions that affected an address but were not sent by it:
const stream = grpcClient.ledgerService.listTransactions({
	filter: {
		terms: [
			{
				literals: [
					{
						negated: false,
						predicate: {
							oneofKind: 'affectedAddress',
							affectedAddress: { address: '0xabc...' },
						},
					},
					{
						negated: true,
						predicate: { oneofKind: 'sender', sender: { address: '0xabc...' } },
					},
				],
			},
		],
	},
	readMask: { paths: ['digest'] },
});

for await (const frame of stream.responses) {
	if (frame.transaction) {
		console.log(frame.transaction.digest);
	}
}
```

Transaction predicates are `sender`, `affectedAddress`, `affectedObject`, `moveCall`, `emitModule`,
`eventType`, `eventStreamHead`, and `packageWrite`. Event predicates are `sender`, `emitModule`,
`eventType`, and `eventStreamHead`. An absent filter matches everything; a present filter must have
at least one term.

#### Scan frames, watermarks, and resumption

Every list RPC is a server stream of frames rather than a single response. A frame either delivers
one matching item or only reports scan progress, and every frame carries a `watermark` whose
`cursor` is a safe resume point. Exactly one frame of a successful stream carries `end`, which
reports why the scan stopped:

| `end.reason`       | Meaning                                                          |
| ------------------ | ---------------------------------------------------------------- |
| `ITEM_LIMIT`       | The requested item limit was reached; that frame carries an item |
| `SCAN_LIMIT`       | The server's per-request scan budget was exhausted               |
| `CHECKPOINT_BOUND` | A requested checkpoint range bound was reached                   |
| `CURSOR_BOUND`     | An exclusive cursor bound was reached                            |
| `LEDGER_TIP`       | The scan reached the currently indexed ledger tip                |

Pass `options` to bound and order a scan. `after` and `before` are canonical ledger-position bounds
that keep the same meaning in both directions — ordering only controls the order of items within the
resulting interval — and they intersect with `startCheckpoint`/`endCheckpoint` when both are given:

```typescript
import { GrpcTypes } from '@mysten/sui/grpc';

let resumeFrom: Uint8Array | undefined;

const stream = grpcClient.ledgerService.listEvents({
	readMask: { paths: ['event_type', 'transaction_digest', 'event_index'] },
	startCheckpoint: 1_000_000n,
	options: {
		after: resumeFrom,
		limit: 100,
		ordering: GrpcTypes.Ordering.ASCENDING,
	},
});

for await (const frame of stream.responses) {
	// Track the latest watermark: it is always the safe place to resume from
	resumeFrom = frame.watermark?.cursor ?? resumeFrom;

	if (frame.event) {
		console.log(frame.event.eventType, frame.event.transactionDigest);
	}
}
```

A `SCAN_LIMIT` end reason means the scan stopped before reaching the bound, not that the results are
exhausted — issue the next request with `options.after` set to the last watermark cursor to keep
making progress.

## Subscriptions

gRPC is the only transport with real-time push. `grpcClient.subscriptionService` provides filtered
server streams of checkpoints, transactions, and events:

| Method                  | Yields                                          |
| ----------------------- | ----------------------------------------------- |
| `subscribeCheckpoints`  | Checkpoints, and progress-only cursor frames    |
| `subscribeTransactions` | Executed transactions, and progress-only frames |
| `subscribeEvents`       | Emitted events, and progress-only frames        |

Each subscription pairs with the ledger service `List` RPC of the same name: it takes the same
filter message and its frames carry the same item and watermark shapes, with identical cursor
semantics.

```typescript
import { SuiGrpcClient } from '@mysten/sui/grpc';

const grpcClient = new SuiGrpcClient({
	network: 'testnet',
	baseUrl: 'https://fullnode.testnet.sui.io:443',
});

const stream = grpcClient.subscriptionService.subscribeTransactions({
	filter: {
		terms: [
			{
				literals: [
					{
						negated: false,
						predicate: { oneofKind: 'sender', sender: { address: '0xabc...' } },
					},
				],
			},
		],
	},
	readMask: { paths: ['digest', 'effects.status'] },
});

for await (const frame of stream.responses) {
	if (frame.transaction) {
		console.log(frame.transaction.digest, frame.transaction.effects?.status?.success);
	}
}
```

Filters use the same DNF structure as the [raw list RPCs](#raw-list-rpcs). Omit `filter` to receive
every item.

### Frames and watermarks

A subscription behaves like an unbounded ascending scan. Every frame carries the subscriber's resume
point, so a frame may report progress without delivering an item:

- `subscribeTransactions` and `subscribeEvents` frames carry `watermark` on every frame, and
  `transaction` or `event` only when the frame delivers a match.
- `subscribeCheckpoints` frames are checkpoint-granular, so they carry a `cursor` sequence number
  instead of a watermark, plus `checkpoint` when the checkpoint matched.

Two delivery guarantees keep sparse filters alive: the first frame of a filtered subscription is
always a progress-only frame that establishes the stream's start position, and progress keeps
advancing with bounded staleness even while nothing matches.

```typescript
let lastCursor: Uint8Array | undefined;

for await (const frame of stream.responses) {
	// Every frame advances the resume point, including progress-only frames
	lastCursor = frame.watermark?.cursor ?? lastCursor;

	if (!frame.transaction) {
		continue;
	}

	await handleTransaction(frame.transaction);
}
```

Checkpoint streams track a sequence number instead. An unfiltered checkpoint stream delivers every
frame with both fields set, in order and without gaps:

```typescript
const checkpoints = grpcClient.subscriptionService.subscribeCheckpoints({
	readMask: { paths: ['sequence_number', 'digest', 'summary'] },
});

let lastCheckpoint: bigint | undefined;

for await (const frame of checkpoints.responses) {
	lastCheckpoint = frame.cursor ?? lastCheckpoint;

	if (frame.checkpoint) {
		console.log(frame.checkpoint.sequenceNumber, frame.checkpoint.digest);
	}
}
```

### Cancelling a subscription

Subscription streams have no successful end — they run until the client cancels them or the server
terminates them with a gRPC status. Pass an `AbortSignal` through `RpcOptions` to cancel:

```typescript
const controller = new AbortController();

const stream = grpcClient.subscriptionService.subscribeEvents(
	{ readMask: { paths: ['event_type', 'transaction_digest'] } },
	{ abort: controller.signal },
);

// Later, to tear the stream down
controller.abort();
```

### Recovering missed data after a disconnect

Subscriptions do not support resumption: a new subscription always starts at the current tip of the
chain as seen by the server, so anything that happened while you were disconnected is skipped.
Replay the gap with the paired `List` RPC before resuming live delivery.

Scan the interval between the last cursor you processed and the cursor the new subscription started
at, by passing them as `options.after` and `options.before` (for checkpoints, use
`startCheckpoint`/`endCheckpoint` with the corresponding sequence numbers instead). The indexed tip
that `List` reads from may trail the subscription's start position, so repeat the call until a scan
actually reaches the upper bound, which the terminal frame reports as `CURSOR_BOUND`:

```typescript
import { GrpcTypes } from '@mysten/sui/grpc';

async function replayGap(after: Uint8Array, before: Uint8Array) {
	let cursor = after;

	while (true) {
		const stream = grpcClient.ledgerService.listTransactions({
			readMask: { paths: ['digest'] },
			options: { after: cursor, before, limit: 100 },
		});

		let reason: GrpcTypes.QueryEndReason | undefined;

		for await (const frame of stream.responses) {
			cursor = frame.watermark?.cursor ?? cursor;
			reason = frame.end?.reason ?? reason;

			if (frame.transaction) {
				await handleTransaction(frame.transaction);
			}
		}

		// The bound was reached: the gap is fully replayed
		if (reason === GrpcTypes.QueryEndReason.CURSOR_BOUND) {
			return;
		}

		// The scan stopped at the indexed tip — wait for the index to catch up
		if (reason === GrpcTypes.QueryEndReason.LEDGER_TIP) {
			await new Promise((resolve) => setTimeout(resolve, 1000));
		}
	}
}
```

A durable consumer therefore keeps two pieces of state: the last cursor it processed, and the start
cursor reported by the first frame of each new subscription. On reconnect, start the subscription
first, buffer its frames, replay the gap between those two cursors, then process the buffer.

<Callout type="info">
	Subscriptions work over both the default gRPC-web transport and the native gRPC transport. In a
	browser, long-lived streams are subject to normal connection limits and proxy timeouts, so treat
	disconnects as routine and always implement the replay path above.
</Callout>

For polling-based alternatives on the other transports, see
[live data over GraphQL](/sui/clients/graphql#subscriptions-and-live-data).
